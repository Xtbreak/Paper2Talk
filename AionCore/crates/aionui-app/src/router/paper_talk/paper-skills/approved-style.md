# 现代学术：已确认的默认 PPT 风格

依据：用户于 2026-11-06 确认的 iSEARLE 六页设计与动效样张。后续生成、扩写、替换论文和单页修改沿用本规范；用户明确指定其他模板时才切换。论文检索地区不决定 PPT 风格。

## 每次必须执行的设计流程

1. 先打开同目录 approved-style.png 查看已确认样张的图文层级、重点框和数值对照。只借鉴设计，科学内容与数值必须来自本次论文。先选页型，再写正文。为每页输出 `design`，将讲解关系放入实际字段，导出器不会从备注猜布局。
2. 把每页主要任务写成一句结论标题。`subtitle` 交代对象、条件或图的阅读方向；`body` 作为页底结论，约 60 字以内。原理细节进入 `points` 和原图阅读顺序，备注补全口头讲稿。
3. 方法全图与局部原理分开。原图中本页要读的部分应占图像主要面积；窄竖图先裁取目标行/模块，保留标签和连线。不能继续沿用上一版“小图 + 右侧一段正文”。复杂多行图只裁本页要讲的代表行或模块，标题/图注注明局部，其余由原文链接回查；不为“方法全图”把整页小字塞入一页。在导出前实际查看裁图；关键标签在幻灯片上应接近正文可读尺度。
4. 创新/设计区别用对照行；实验用原图或原表配原生数值比较；方法图用编号框对应讲解步骤。每个标注和图表值都要定位到原文，设计元素不凭空增加科学含义。
5. 检查整份至少包含四类页型。6–8 页单篇默认：封面 → 问题/创新对照 → 方法全图 → 局部原理 → 实验证据 → 讨论，证据多时扩为两页。评测论文使用协议设计、受控因素和验证结果，不冒充提出了已有模型。
6. 逐页检查结构是否可执行：图框在图内、每个指标轴从零开始且能容纳所有值、比较标签/单位/精度与原表一致；原图不被标注遮挡。原图、结论、备注和手动数值修改一并保留。

## 结构化视觉契约

`outline` 每页保留 title、body、notes、seconds、evidence、figure、table，另外必须有 `design`。`body` 始终显示在页面上，不能只把细节放备注。字段名严格如下，未使用的数组给 `[]`：

- `layout`：`cover | concept | comparison | figure | mechanism | evidence | discussion`。
- `subtitle`：约 35 字内，说明上下文或阅读方向；`key`：可为空，概念、公式、短流程或封面研究对象。不要把整个英文论文题名塞进 key。
- `points`：`[{"title":"步骤标题","text":"具体解释"}]`。concept/mechanism 1–3 组，discussion 2–4 组；每组标题约 10 字、解释约 24 字。cover 最多 1 组作为图说明，其余页型为空。
- `comparisons`：`[{"label":"改动位置","baseline":"原有做法","change":"本文设计","effect":"作用"}]`。仅 comparison 使用 2–3 行，各格约 12 字；`key` 可放继承路线，例如 `旧方法 → 改动 → 输出`。此页不放 figure/table。
- `annotations`：`[{"label":"框选内容","rect":[x,y,width,height]}]`。坐标相对当前 figure PNG，左上为 [0,0]、右下为 [1,1]。最多 3 个框，编号按数组顺序。先查看裁图再定坐标；框线沿目标边缘，编号旁边留空，不挡公式和箭头。concept/mechanism 的编号与 points 顺序对应。
- `metrics`：仅 evidence 使用 1–2 组 `{"label":"指标名","unit":"单位","baseline_label":"基线","baseline":0.65,"result_label":"新条件","result":0.85,"axis_max":1.0,"decimals":2}`。原生条形图统一从 0 起，轴上界必须覆盖数值；同一指标使用同一上界。差值由程序计算，明确是绝对差、百分点还是原单位；DSC 0–1 的差值不能写成百分比。

页型布局：cover 使用深色标题区 + 独立浅色原图区，必须提供短 key 和 figure；concept/mechanism 使用大原图 + 重点概念/步骤；figure 使用全宽原图和编号定位；comparison 使用横向对照行；evidence 左侧原图/原生表格、右侧指标条形图；discussion 用编号结论与可执行下一步。concept/mechanism/figure 必须有 figure；evidence 必须有原表 table 或 figure+metrics。evidence 的 table 与 figure 二选一，不重复塞两份表；既有手动数值必须保留到新的可编辑表或 metrics。其他页型 table 为空。每一项内容都必须有对应可见元素。

示例（仅展示 design；该页另有含原始数值的 figure 与 evidence）：
```json
{"layout":"evidence","subtitle":"同模型、同测试集 · DSC 中位数 · 0–1","key":"","points":[],"comparisons":[],"annotations":[{"label":"基线与目标条件","rect":[0.02,0.3,0.96,0.5]}],"metrics":[{"label":"DSC","unit":"绝对差（0–1）","baseline_label":"Point","baseline":0.65,"result_label":"Mask3","result":0.85,"axis_max":1.0,"decimals":2}]}
```
示例数字只有对应论文原表证实才能使用。图框坐标也是示例，必须按实际裁图重定。

## 固定视觉规范

- 16:9，33.87 × 19.05 cm。正文页用暖白 `F6F5F1`，主文字炭灰 `182E33`，主色蓝绿 `0A7472`，创新和关键差值用少量橙色 `D66B3D`，说明文字 `637575`，浅底 `E4EEEA`，分隔线 `CAD5D1`。同一颜色保持同一含义，强调同时配文字或编号。
- 封面使用炭灰与暖白分栏，大标题、研究对象和真实图像构成主要画面。正文页保留统一的栏目、页码、来源位置和页数进度，内容围绕原图或关键证据展开。
- 中文使用清晰无衬线字体；macOS 用 PingFang SC，其他平台用 Microsoft YaHei。英文及公式可用 Arial / Cambria Math。标题 36–44 pt，正文 18–22 pt，来源和页码 10–12 pt。原图中文字通过裁切和放大保证可读；内容过多时拆页。
- 页面左右边距约 1.4 cm，图文间距至少 0.75 cm。统一对齐、留白与字号层级。标注与正文分层，编号放在原图空白处或图外，保留损失项、箭头、坐标轴、图例和数据。
- 设计元素采用章节编号、信息流程箭头、对比行、局部聚焦框、关键数值和进度标记。每个元素对应具体内容，不用随机装饰、贴纸、渐变卡片或满页色块填空。

## 根据内容选择页型

| 页型 | 组织方式 | 阅读重点 |
| --- | --- | --- |
| 封面 | 深色标题区 + 浅色原图区 | 研究对象、问题与具体例子 |
| 研究问题 | 真实任务例图 + 简短概念解释 | 输入、期望输出与困难 |
| 创新对比 | 继承内容单列，再逐行对照改动位置、新设计、作用 | 相对谁改了什么 |
| 方法全图 | 原图占主要面积，少量编号建立阅读顺序 | 整体数据流和改动位置 |
| 局部原理 | 原图局部放大 + 符号、操作、作用解释 | 每一步怎样工作 |
| 实验证据 | 保留原图/原表，旁边转写关键对照或差值 | 哪个实验支持哪项创新 |
| 讨论 | 简短结论 + 具体局限或可执行的下一步 | 从证据得到什么判断 |

同类页复用同一布局，跨页型改变画面重心。六页是风格样张，不是固定页数：每篇论文仍须展开问题、具体创新、原理、验证与局限。

## 原图与内容

- 关键方法和实验使用可追溯到 PDF 页码的原图，保持比例和原始数据。完整方法图用于建立全局，再用真实子图解释机制；局部必须注明来源和“局部放大”。
- 新增标注、公式解释和数据转写保持可编辑，与原图分离；概念示意明确标为示意。不能把 AI 重绘当作论文原图。
- 单页标题尽量在 28 个中文字以内，正文约 90 字以内、最多 4 个讲解单元。新写的并列要点按行提供，由生成器统一编号；已有手动编号保留。公式页解释符号与直觉；实验页保留数据集、划分、指标、单位和比较条件。单位、精度、正负号与原文一致。
- 原理必须出现在正文与原图阅读路径中，备注补全口头解释，不用删掉创新细节换取视觉简洁。手动修改和指定保留页优先，只调整受本次请求影响的内容。

## 动效约束

- 普通翻页采用约 400 ms 淡化；页内解释采用约 350 ms 淡入，以点击推进，每步只引入一个解释单元。图和核心标题先可见，再出现解释或强调。
- 连续两页使用同一张原图且确实改变位置或尺寸时，可用约 800 ms Morph；保留相同对象名称，转场服务于全图到局部的讲解。不同原图采用淡化。
- 原生动画必须写进 PPTX；HTML 示意和静态预览不能作为原生播放验收。默认由演讲者翻页，不设置自动翻页、循环动画或随机效果。
- 静态终态也要完整可读。WPS 为用户当前使用环境；未在该版本 WPS 实播时明确记为未验证，不声称 Morph 兼容性已经通过。兼容回退只能改变转场，不能损失内容。

## 交付检查

逐页检查字号、裁切、原图比例、标注遮挡、颜色含义与正文密度；逐个核对实验数字及原文出处。检查点击顺序、动画目标、备注、手动改动与完整页数。任何溢出或遮挡应先调整布局或拆页；不得通过缩小字号、删除机制或修改数据通过检查。报告文件结构检查、静态排版检查、原生播放检查各自的结果。
